# Dalu (Windows Notch Overlay)

Apple Music / Cider(포트 10767)와 연동되고, Cider가 아닌 앱(Spotify·브라우저 등)의 미디어도 보여 주는 Windows 노치 오버레이입니다.
가사·재생 컨트롤뿐 아니라 포모도로, 물 마시기, 파일 선반, 할 일, 시스템 알림(볼륨·밝기·Caps Lock·입력 언어·충전기·네트워크·헤드폰)과 캐릭터(눈)를 포함합니다.

## ✨ 기능

- **가사**: 스트리밍(Cider) 가사 우선(단어 단위 > 줄 단위), 줄 클릭 시 해당 지점으로 이동. **가사 버튼**(또는 우클릭 메뉴)으로 표시 켜기/끄기 — 끄면 곡 정보만 보입니다.
- **어떤 앱의 음악이든**: Cider가 재생 중이면 Cider(가사까지)를, 아니면 윈도우 미디어 컨트롤에 올라온 다른 앱의 곡을 보여 주고 같은 컨트롤로 제어합니다. 재생 중인 쪽이 우선이고, 둘 다 재생 중이면 보던 쪽을 유지하며, 둘 다 멈춰 있으면 보던 곡을 그대로 둡니다(`smtc.choose_source`). Cider가 꺼져 있어도 동작합니다. 다른 앱의 곡은 제목·아티스트·곡 길이로 NetEase와 LRCLIB를 동시에 조회해 단어 싱크 > 줄 싱크 > 싱크 없음 순으로 가장 좋은 가사를 씁니다(이 두 서비스에는 곡 정보만 전송, 같은 곡 재조회는 캐시). 곡 길이가 4초 넘게 다르면(라이브/리믹스) 다른 버전으로 보고 건너뜁니다. 앱이 반복/셔플을 지원하지 않으면 두 버튼이 흐려집니다.
- **FluentFlyout 류 기능**: Num/Scroll Lock 알림, 키보드 미디어 키를 누르면 곡 정보 표시, 곡이 끝나기 전 **다음 곡(Up Next)** 미리 보기(Cider 대기열), 다른 앱 미디어 **앱 필터**(허용/제외 목록), **볼륨 믹서**(설정 창, 마스터+앱별). 모두 설정 창에서 켜고 끌 수 있습니다.
- **셔플 / 반복**: 반복은 끔 → 전체 → 한 곡 순환(Apple Music과 같은 순서).
- **비주얼라이저**: PC 출력 오디오의 저음~고음 5개 대역에 반응합니다. 소리는 대역 크기를 계산하는 데만 쓰고 저장·전송하지 않으며, 화면에 보일 때만 계산합니다. 사용할 수 없으면 자체 불규칙 움직임으로 대체됩니다. (주의: Cider만이 아니라 PC에서 나오는 모든 소리에 반응)
- **이어버드(갤럭시 버즈)**: 연결되면 알림으로 배터리를 보여 주고, 페이지에서 좌/우/케이스 배터리와 소음 제어 모드(끄기 · 주변 소리 듣기 · 소음 제어 최적화 · 액티브 노이즈 캔슬링)를 설정합니다. 배터리 부족(20%)도 알려 줍니다. 에어팟은 지원하지 않습니다(아래 참고).
- **애니메이션**: 가사를 켜면 컨트롤 패널이 왼쪽으로 이동하며 가사가 오른쪽에서 스며들고, 끄면 반대로 움직입니다. 앨범 아트는 접힘 → 알림 → 음악 → 가사 사이를 하나의 요소가 크기·위치를 바꾸며 이동하고, 페이지 전환은 방향 있는 슬라이드 + 항목 순차 등장입니다. Windows의 "애니메이션 효과 끄기" 설정을 따릅니다.
- **포모도로** 집중/휴식, 완료 시 알림음. **물 마시기** 병 크기·목표·알림 간격/시간대, 시간대별 차트. **할 일** 시각 지정 알림. **파일 선반** 탐색기에서 끌어다 놓기, 카드를 끌어 다른 앱으로 내보내기, 클릭하면 열기.
- **시스템 알림**: 볼륨, 밝기(노트북 내장 패널), Caps Lock, 입력 언어, 충전기 연결/분리, 배터리 부족, 인터넷 연결/끊김, 헤드폰 연결.
- **전체화면 앱**이 켜지면 '항상 위'를 풀어 양보합니다.
- 설정/할 일/기록/선반은 `%APPDATA%\Dalu\island\data.json`(이 PC)에만 저장됩니다. 한국어/영어 전환은 우클릭 메뉴.

## 🔧 동작 메모

- **가사 전달**: `get_state(known_lyrics_version)` — 가사는 버전이 바뀔 때만 응답에 포함. 곡이 바뀌면 `lyrics: null` 이 내려와 이전 곡 가사가 즉시 지워집니다.
- **가사 조회**: 별도 스레드에서 카탈로그 ID(없으면 라이브러리 ID) 순으로 조회, 응답 대기 8초. Cider가 `404 LYRICS_NOT_FOUND` 를 두 번 확답하면 즉시 "가사 없음"을 보여 주고, 타임아웃 등 불확실한 경우엔 약 30초 재시도 후 20초 간격으로 몇 번 더 시도합니다. 실패 이유는 `app.log` 에 남습니다.
- **로컬 TTML**: `%APPDATA%\Dalu\lyrics\*.ttml` 은 스트리밍 가사가 줄 단위이거나 없을 때만 쓰입니다("파일명에 제목+아티스트 포함" 또는 "파일명 == 제목").
- **시간 정보 없는 가사**: 하이라이트 없이 스크롤 가능한 정적 목록으로 표시.
- **pythonnet 주의**: `sysmon.py`·`audiolevels.py` 는 ctypes 만 씁니다. 웹뷰가 .NET 을 초기화하는 동안 다른 스레드에서 .NET 객체를 만들면 프로세스가 `NullReferenceException` 으로 죽습니다.
- **클릭 투과 모드**: 켜면 창이 마우스를 받지 못하므로, **창 위에 커서를 올리고 Ctrl 키를 누르면 해제**됩니다.
- **우클릭 메뉴**: 열 때 창 높이를 일시적으로 키우고, 닫으면(바깥 클릭/Esc/포커스 상실) 원래대로 돌아옵니다.
- **창 크기 상수**: `dalu.py` 의 `EXPANDED_*` / `NOTCH_*` 와 `app.js` 의 `STATES`, `island.css` 의 `.island[data-s=...]` 크기는 서로 맞아야 합니다.
- **창 크기 보정**: pywebview 는 프레임 없는 창을 요청보다 작게 만들어(150% DPI 에서 높이 약 37px, 폭 약 14px 부족) 노치가 중앙에서 어긋나므로, 창이 뜬 직후 `recenter_window()` 로 정확한 크기·위치를 맞춥니다.
- **클릭 영역·그림자**: 노치 + 귀 + 스프링 오버슈트 여유(좌우 `귀+12px`, 아래 약 10px)만 클릭되고 나머지는 통과합니다. 창이 그 영역으로 잘리므로 노치 그림자는 그 안에서 끝나는 작은 그림자여야 경계가 보이지 않습니다.
- **단어 공백**: 가사 단어에 `space`(뒤에 공백이 있었는지)를 실어 보내, 음절 단위 가사가 "Hel lo" 로 갈라지지 않게 합니다.

## 🎧 이어버드 메모

- **배터리**: 연결된 BLE 장치의 GATT Battery Service(0x180F)를 20초마다 읽습니다. 좌/우/케이스는 각 특성의 Presentation Format 디스크립터(Bluetooth SIG 네임스페이스 `0x010D` left, `0x010E` right, `0x0110` external=케이스)로 구분합니다.
- **소음 제어**: 삼성 버즈의 독자 프로토콜(RFCOMM 서비스 `2e73a4ad-332d-41fc-90e2-16bef06523f2`)로 `SET_NOISE_CONTROLS(0x78)` 를 보내고 확인 응답(`0x42`)을 기다립니다. 프레임은 `FD | 길이(2바이트 LE) | id | payload | CRC16-XMODEM(LE) | DD` 이며 Galaxy Buds3 Pro 실제 트래픽으로 검증했습니다. 제어 연결은 **버즈 페이지를 열 때 미리 맺고**(첫 연결은 블루투스 링크 설정이라 2~6초 걸린다), 마지막 사용 후 60초 동안만 유지합니다(폰의 Galaxy Wearable 앱과 덜 충돌하도록). 연결된 동안 모드 변경은 약 0.1초입니다. 서비스 조회(SDP) 결과는 캐시합니다 — 매번 `UNCACHED` 로 조회하면 1.5~5초가 걸리고 간헐적으로 "서비스를 찾을 수 없음"으로 실패했습니다. **확인 응답(`0x42`)의 두 번째 바이트는 상태 코드가 아니라, 0이거나 적용된 모드 번호 그대로(에코)입니다** — 둘 다 성공으로 처리합니다(`ack_ok`). 이전에는 0만 성공으로 읽어서, 모드가 정상 적용돼도 끄기 외에는 "실패"로 표시했습니다. 그 밖의 값이면 잠깐 뒤 최대 2번 다시 보냅니다. 모든 명령의 단계별 시간과 실패 이유는 `app.log` 에 남습니다.
- **한계**: 버즈가 현재 소음 제어 모드를 알려 주는 메시지를 찾지 못해, 화면의 선택 표시는 **이 앱에서 마지막으로 설정한 값**입니다(폰/터치패드로 바꾼 것은 반영되지 않습니다). 모드 번호(0 끄기 · 1 ANC · 2 주변 소리 · 3 어댑티브)는 `buds.py` 의 `MODE_*` 와 `features.js` 의 `BUDS_MODES` 에서만 정의합니다.
- **AirPods**: Windows에서 노이즈 컨트롤을 바꾸는 데 필요한 L2CAP 채널을 앱이 열 수 없고, 배터리는 BLE 광고 패킷 해석이 필요해 이번에는 넣지 않았습니다.
- 서비스는 `winrt-*` 가 없으면 조용히 비활성화되고 나머지 기능은 그대로 동작합니다.

## ⚡ 성능 메모 (실측)

- **`dragover` 를 파이썬 DOM 이벤트로 등록하지 않는다**: 파일을 끄는 동안 초당 수십 번 발생하는데, pywebview 는 이벤트마다 브리지를 타고 스레드를 만들어서 화면이 약 10fps 로 떨어졌습니다(3초에 180프레임이 나와야 하는데 33프레임). 경로 수집에는 `drop` 리스너만 필요합니다.
- **선반 썸네일은 파이썬이 축소해서 준다**(`get_thumbs`, PIL, JPEG 는 축소 디코딩, 디스크 캐시 `thumbs/`). 원본(수십 MB)을 `<img>` 로 그대로 쓰면 화면 스레드에서 통째로 디코딩해 250ms 이상 끊겼습니다.
- 드롭된 경로는 다음 폴링을 기다리지 않고 `pollNow()` 로 즉시 가져갑니다(드롭 → 카드 표시 약 17ms).
- 프레임 간격은 실제 WebView2 창에서 확장/축소, 가사 토글, 페이지 전환, 비주얼라이저 동작 중 모두 16.7ms(60fps) 로 유지됩니다.
- **다른 프로그램이 GPU를 쓸 때(영상 재생 등)의 끊김**: DevTools 추적(`PipelineReporter`)으로 GPU 부하를 걸어 재현했고(손실 프레임 평균 0.9%, p50 22ms), 비용 큰 효과를 줄여 0.1% / 16.7ms 로 내렸습니다 — 레이어 전환의 `blur` 필터 제거(배경이 순수 검정이라 효과가 없음), 보이지 않는 레이어는 `visibility:hidden`, 앰비언트 애니메이션은 음악/가사 화면에서 재생 중일 때만, 토스트의 `backdrop-filter` 제거, 의미 없는 `will-change: width, height` 제거.
- **휠/트랙패드로 페이지 넘기기는 '제스처 하나에 한 번'**: 예전에는 고정 380ms 잠금이라, 트랙패드 관성 스크롤(1초 넘게 이벤트가 이어짐) 한 번에 페이지가 9번 연달아 넘어가며 애니메이션이 계속 끊겨 다시 시작됐습니다(실측). 이제 이벤트가 170ms 이상 끊길 때까지를 한 제스처로 보고, 누적량이 50을 넘으면 한 번만 넘깁니다(방향이 바뀌면 새로 시작, 연달아 넘기는 간격은 최소 350ms). 마우스 휠 한 칸씩은 칸마다 한 번씩 넘어갑니다. 가사의 양은 전환 비용에 영향이 없음을 확인했습니다(400줄에서도 전환 함수 동기 비용 약 3ms).
- **알림 갱신**: 볼륨/밝기처럼 계속 바뀌는 알림은 이미 떠 있으면 등장 애니메이션을 다시 재생하지 않고 막대·숫자만 갱신하며 표시 시간만 연장합니다(`notify` 의 `key`).

## 🔮 Liquid Glass (설정 창)

설정 창의 작은 컨트롤(버튼, 스위치·슬라이더 손잡이, 선택 막대, 아이콘 구슬)은 흐림만 있는 유리가 아니라 **가장자리에서 뒤의 화면을 굴절**시키는 렌즈입니다(`glass.js`: 캔버스로 만든 변위 맵 + SVG `feDisplacementMap`, 색 번짐 포함). 테두리의 반사광과 마우스를 따라가는 하이라이트는 CSS 입니다. 큰 카드는 비용 때문에 반사광만 씁니다. 굴절을 못 쓰는 환경에서는 알아서 흐림+반투명으로 돌아갑니다. 노치는 아래 “노치 리퀴드 글래스”를 보세요.

## 🕒 작은 노치

설정 › 모양·동작 › 작은 노치를 켜면 접힌 노치가 더 작아지고, 음악이 나올 때 가운데에 **현재 시간**이 표시됩니다(“작은 노치에서 시계 표시”로 끌 수 있음).

## 🔮 노치 리퀴드 글래스

설정 › 모양·동작 › **노치 리퀴드 글래스**: 끔 / 컨트롤 / 전체.

- **컨트롤**(기본): 노치 안의 재생 버튼, 알약 버튼, 타일, 칩이 굴절 렌즈가 됩니다. 뒤에 깔린 앨범 색 빛이 가장자리에서 휘어 보이고, 테두리에 반사광이 돌며 마우스를 따라 하이라이트가 움직입니다.
- **전체**: 위에 더해 노치 본체가 뒤의 화면을 비춥니다(`deskcap.py`). 노치 창이 투명해서 CSS 로는 바탕을 읽을 수 없으므로, 파이썬이 노치 뒤 화면을 작게(160px) 찍어 초당 2~3번 넘기고 화면(HTML)이 흐리게 깔아 가장자리를 굴절시킵니다. 윗부분은 검정으로 남아 베젤과 이어지고, 아래로 갈수록 비칩니다.
  - 이때 노치 창이 자기 자신을 찍지 않도록 **노치 창만 화면 캡처에서 제외**합니다(`SetWindowDisplayAffinity`, Windows 10 2004 이상). 그래서 이 모드에서는 화면 녹화·스크린샷에 노치가 찍히지 않아요. 끄면 바로 되돌아갑니다.
  - **스크린샷·영상 녹화에서 노치**(설정 › 모양·동작 › 노치 리퀴드 글래스, 가리기 / 자동 / 표시):
    - **가리기**: 위처럼 노치 창을 캡처에서 빼서 뒤 화면이 실시간으로 비치지만, 캡처에는 노치가 안 찍힙니다.
    - **자동**(기본, `capturewatch.py`): 평소엔 가리다가 `PrintScreen`, `Win+Shift+S`, `Win+Alt+R`, `Win+Shift+R`을 누르거나 OBS·반디캠 같은 녹화 프로그램이 켜져 있는 동안만 노치가 찍히게 합니다(그동안 뒤 화면은 멈춥니다). 키는 누른 직후에 풀어 주는 방식이라 아주 빠른 PrintScreen은 놓칠 수 있습니다.
    - **표시**: 항상 찍히고, 뒤 화면은 정지 화면이 됩니다.
  - **NVIDIA(지포스) 녹화**: 창을 캡처에서 제외하면 NVIDIA 녹화가 그 창을 “보호된 콘텐츠”로 보고 **바탕화면 녹화를 거부**할 수 있습니다(NVIDIA 로그에 `NVFBC_ERROR_PROTECTED_CONTENT`, 앱 이름 “Python”). 이때는 “표시”로 바꾸고 녹화하세요.
  - **캡처 모드 단축키**(`Ctrl+Alt+P`, 켜져 있을 때 다시 누르면 꺼짐): 15초 동안만 임시로 뒤 화면을 얼려 두고 노치를 캡처에 보이게 합니다(“표시”일 때는 이미 항상 켜져 있습니다). NVIDIA 녹화 단축키 `Alt+F9`도 알아채서 같은 일을 하지만(다시 누르면 끔) 녹화가 시작되는 순간보다 늦을 수 있어 확실하지 않습니다.
  - 지원하지 않거나 첫 화면이 오기 전에는 원래의 검정 노치로 보입니다.


## 🎞 뒤 화면 스트림 (노치 리퀴드 글래스 '전체')

프레임을 웹뷰에 스크립트로 하나씩 밀어 넣으면 초당 30장 정도가 한계라서, 파이썬이 `127.0.0.1`의 무작위 포트·무작위 주소에서 `multipart/x-mixed-replace` 이미지 스트림을 열고 노치 화면이 그 주소를 `<img>`로 직접 받습니다. 뒤 화면이 움직이는 동안 목표 60fps, 1초 넘게 안 바뀌면 10fps로 쉽니다. 주소의 토큰을 모르면 열 수 없고, 본인 PC 밖에서는 접근할 수 없습니다.

## 🎤 백그라운드 보컬 (에코/애드립)

TTML 가사에서 본 가사를 따라 부르는 에코·애드립은 `role="x-bg"` span 이거나 소괄호로 감싼 줄로 내려옵니다. 예전에는 이 줄이 본 줄과 시간이 겹쳐서 본 줄을 끝나기 전에 가로채거나, 안쪽 단어가 통째로 빠졌어요.

- 본 가사와 따로 파싱해서 `lyrics.bg` 로 분리하고, 괄호는 떼어 냅니다(`cider_client.py`: Cider API 의 `isBackground`, 표시가 없어도 앞 줄과 겹쳐 시작하는 `(...)` 줄, TTML `x-bg` 를 모두 인식). 본 가사가 없는 곡은 손대지 않아요.
- **작은 노치**: 에코가 0.8초 이상 이어질 때만 노치가 아래로 조금(32 → 56px) 늘어나 본 줄 밑에 작은 줄로 단어 하이라이트와 함께 보여 주고, 끝나면 접힙니다. 첫 줄(아트·가사·막대)은 위에 그대로 있어요. 더 짧은 에코는 노치가 들썩이지 않게 건너뜁니다.
- **가사 목록(펼친 상태)**: 본 줄 아래에 작은 글씨로 끼워 넣고, 부르는 동안 밝아집니다.

## 📐 노치 크기 · 고정 위치

- 설정 › 화면 › **노치 크기**(80~200%): 노치와 안의 글자·버튼·가사·보조 노치가 함께 커지고 작아집니다. WebView2 확대 배율(`ZoomFactor`)로 처리하고 창 크기도 같이 맞춥니다.
- 노치는 **끌어서 옮길 수 없습니다**(위치는 선택한 모니터 위쪽 가운데로 고정). 위치를 다시 맞추려면 설정 › 화면 › “노치를 화면 가운데로”.
- 애니메이션 설정은 노치용과 설정 창용이 **따로**입니다(설정 › 애니메이션). 애니메이션 미리보기만 노치 설정을 따릅니다.

## 🏝 보조 노치 = 물방울 (다이나믹 아일랜드식)

음악이 나오는 접힌 노치 옆에 **물방울 모양의 작은 노치**가 따로 떠 있습니다(`satellite.js`). 큰 노치는 계속 가사를 보여 주고, 물방울은 진행 중인 것을 보여 줘요.

- 포모도로/타이머가 돌고 있으면 링 + 남은 시간, 스톱워치는 **아이콘** + 지난 시간(끝이 없어서 줄어드는 링은 쓰지 않아요), 아무것도 없으면 현재 시간. 누르면 노치가 펼쳐지며 그 페이지가 열립니다.
- **보조 노치는 두 개, 하나에 정보 두 개까지**(최대 네 개): 오른쪽이 먼저 나오고 그 뒤(약 1초)에 왼쪽이 나옵니다. 앞선 항목(포모도로 > 타이머 > 스톱워치 > 시계)부터 오른쪽을 채우고 절반씩 나눠요(1개: 오른쪽 / 2개: 한 개씩 / 3개: 오른쪽 둘 + 왼쪽 하나 / 4개: 둘씩). 한 노치에 정보가 둘이면 폭이 넓어지고 가운데에 구분선이 생기며, 누른 쪽 항목의 페이지가 열립니다. 타이머와 스톱워치는 서로 독립이라 하나를 돌려 둔 채 다른 하나를 쓸 수 있습니다. 왼쪽은 오른쪽 레이어를 좌우로 뒤집은 것이라(`.goo-l`, `.sat-wrap-l`) 노치가 왼쪽으로 먼저 당겨지는 흔들림도 거울상입니다.
- **나오는 애니메이션**: 큰 노치 안쪽에서 작게 시작해 밀려 나오며 노치와 사이에 잘록한 '목'이 생겼다가 뚝 끊어져 물방울이 떨어져 나가고, 끝에서 한 번 튕깁니다. 사라질 때는 반대로 다시 노치로 빨려 들어가요. (SVG 블러 + 문턱값 '메타볼' 필터로 두 모양이 가까울 때만 이어 붙입니다 — 이 필터는 물방울이 움직이는 동안에만 켜 둬서 평소에는 비용이 없어요. 큰 노치가 투명한 유리일 때는 노치 자리를 마스크로 비워 뒤가 막히지 않게 해요.)
- **디테일**: 큰 노치·물줄기·보조 노치는 따로가 아니라 **하나의 물방울**로 한꺼번에 계산해 매 프레임 그립니다(`satellite.js` 의 `satPlanOut/satPlanIn`: 보조 노치의 위치 p, 큰 노치가 끌려가는 거리 pull, 물줄기 굵기 thick). 보조 노치는 큰 노치가 **완전히 줄어든 뒤**(약 0.8초) 큰 노치의 옆면 **뒤에서** 나옵니다. **나올 때**: 옆면으로 빠져나오며 물줄기가 늘어나고, 늘어난 만큼 큰 노치가 보조 노치 쪽으로 **끌려가다가**(오른쪽 보조 노치면 오른쪽, 왼쪽이면 왼쪽) 물줄기가 끊어지는 순간 놓여서 **좌우로 흔들리며 잦아듭니다**. **들어갈 때**: 끌리듯 다가오며 물줄기가 생기고 큰 노치가 그쪽으로 당겨졌다가, 빨려 들어가면 좌우로 흔들립니다. 물줄기는 매 프레임 큰 노치 옆면에서 보조 노치 안쪽 끝까지 이어 붙어 틈이 없고, 큰 노치의 몸통·가림 영역도 같은 값으로 움직입니다. 리퀴드 글래스 '전체'에서는 물줄기와 물방울 모양도 검정이 아니라 뒤 화면이 비치는 어두운 유리로 채워져서 이어 붙은 부분이 투명 노치와 어울려요. 움직임은 설정의 애니메이션 속도에 맞춰 늘고 줄어요. 큰 노치와 같은 **테마**(검정/유리/앨범 색)와 **리퀴드 글래스 '전체'**(뒤 화면이 비침)를 그대로 따라요. 애니메이션을 끄면 끌림과 흔들림도 없어요.
- 설정 › 모양·동작 › **보조 노치**: 끔 / 타이머만(시계 없이) / 타이머+시계(기본). 켜 두면 큰 노치 안의 예전 타이머 칩은 쓰지 않아요(노치가 넓어지지 않음).
- 작은 노치(compact)에서 “작은 노치에서 시계 표시”가 켜져 있으면 시계는 거기 두고, 물방울은 타이머만 보여 줍니다.

## 🔔 윈도우 알림 동그라미 (`winnotif.py`)

설정 › 알림 › **윈도우 알림이 오면 작은 동그라미로 알리기**(기본 꺼짐). 다른 앱의 윈도우 알림이 오면 큰 노치 옆(왼쪽)에 종 아이콘과 **빨간 점**이 있는 **동그란** 보조 노치가 뜹니다(둘 이상이면 점 안에 숫자). 사라지지 않고 있다가, **누르면 윈도우 알림 센터가 열리면서** 사라지고, 알림 센터를 직접 열거나 윈도우에서 새 알림을 모두 처리해도 사라집니다. 보조 노치가 쓰는 같은 물방울 연출로 나오고 들어갑니다(음악이 없을 때의 작은 노치 옆에도 뜹니다).

- 윈도우 `UserNotificationListener`(`winrt-Windows.UI.Notifications.Management`)로 알림 목록을 1.5초마다 보고, 지난번에 없던 id 를 새 알림으로 봅니다. 알림 **내용(제목·본문)은 읽지도 저장하지도 않고** id 와 앱 이름만 씁니다. 켜는 순간 이미 쌓여 있던 알림은 새 알림으로 치지 않습니다.
- 알림 센터가 열렸는지는 맨 앞 창이 `ShellExperienceHost` 의 '알림 센터'인지로 봅니다(0.4초마다, 새 알림이 쌓여 있을 때만). 열 때는 윈도우 11 이면 `Win+N`, 10 이면 `Win+A` 를 보냅니다(이미 열려 있으면 보내지 않습니다).
- 윈도우 설정 › 개인 정보 및 보안 › 알림에서 알림 접근이 허용돼 있어야 합니다(미설정이면 한 번 요청하고, 안 되면 조용히 꺼 둡니다).

## 🌐 언어 (Languages)

한국어 · English · 简体中文 · 日本語를 지원합니다. 처음 실행하면 윈도우 표시 언어를 따르고(한국어/중국어/일본어가 아니면 English), 설정 › 일반 › 언어 또는 노치를 우클릭한 메뉴의 "언어"로 바꿉니다.
